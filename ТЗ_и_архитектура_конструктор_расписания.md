# Конструктор расписания — архитектура и техническое задание

**Репозиторий:** https://github.com/Nickrrg/schedule_UZ
**Текущая реализация:** `timetable-builder.html` — веб-прототип, один самодостаточный файл.

## 1. Назначение

Инструмент для завуча: собрать данные о школе (классы, предметы, учителя, кабинеты, учебный план) и автоматически сгенерировать конфликтное расписание уроков, с ручной правкой и экспортом в Excel.

Ключевое отличие от существующих на рынке решений (ProRector — десктоп, символическая цена, но результат вручную переносится в eMaktab; edarsjadval.uz — веб, сильный движок на Google OR-Tools, готовит прямую интеграцию с eMaktab): этот инструмент рассчитан на использование **внутри** экосистемы eMaktab, без выгрузки данных на сторону и без обратной интеграции — вся генерация происходит в браузере пользователя.

## 2. Технологическая архитектура

| Слой | Решение |
|---|---|
| Исполнение | Один HTML-файл, ванильный JS (ES5-совместимый синтаксис), без сборки и без фреймворка |
| Хранение | `localStorage` браузера (ключ `timetable_builder_v4`) — данные не покидают устройство завуча |
| Экспорт в Excel | SheetJS (`xlsx.full.min.js`, CDN cdnjs) |
| Экспорт файлов / загрузка | опубликованная веб-страница (Artifact) с capability `downloads`; при недоступности — fallback через `Blob`+`<a download>` |
| Импорт данных | Разбор HTML-таблицы отчёта «Сотрудники» из eMaktab (файл `.xls`, фактически HTML) через `DOMParser` |
| Вёрстка/стиль | Чистый CSS, без Tailwind/Bootstrap; тема — светлая/тёмная/системная |

Никакого бэкенда нет. Всё состояние — один JS-объект `state`, сериализуемый в JSON.

## 3. Модель данных (`state`)

```
state = {
  config: {
    days: 5|6,                 // дней в неделе
    shifts: 1|2,                // смен в школе
    periodsPerShift: number,    // уроков за смену
    schoolType: "criterial"|"classical"
  },
  classes: [{
    id, name, shift,
    grade: 1..11|null,
    studentCount: number|null,
    instructionLang: "uz"|"ru"|"qr",
    jasorat: boolean,                     // направление "Жасорат", 5-6 класс
    track: "none"|"mf"|"kb"|"oc"|"mc"|"ix"|"nd1"|"nd2",  // профиль, 10-11 класс
    trackLang: "uz"|"ru"|"qr",
    firstForeignLang, secondForeignLang,  // "english"|"french"|"german"|...
    technologyMode: "split"|"unified"|"agro",
    officialPlanApplied: boolean
  }],
  subjects: [{ id, name, espId, erpId, roomType: string|null, heavy: boolean }],
  teachers: [{ id, name, subjects:[subjId], maxPerDay, daysOff:[bool x days], homeroomNote? }],
  rooms: [{ id, name, capacity, type: string|null }],
  curriculum: {
    [classId]: {
      [subjectId]: {
        hours, teacherId, unofficial: boolean,
        blockSize: 1|2|3,        // сдвоенный/строенный урок
        syncWith: subjectId|null // групповой урок — связь с другим предметом того же класса
      }
    }
  },
  schedule: {
    byClass: { [classId]: [day][period] -> { lessons:[{subjectId,teacherId,roomId}], locked } | null },
    unplaced: [{classId, subjectId, teacherId}],
    unplacedCount
  }
}
```

Слот времени = `(shift-1) * periodsPerShift + localPeriod` — единая числовая ось на весь день, поэтому 1-я и 2-я смена физически не пересекаются, и учитель, ведущий в обеих сменах, проверяется на конфликт корректно.

## 4. Официальные источники данных, зашитые в код

| Источник | Что взято | Где в коде |
|---|---|---|
| `UZ. Единый справочник предметов` (Confluence-экспорт, версия 1.10) | Полный список из 126 активных предметов ОО с ID ЕСП/ERP | `REAL_SUBJECT_CATALOG` |
| `Sxema_KTP.xlsx` | Официальная сетка часов: 46 предметных строк × база (5-11 класс) × 7 профильных треков 10-11 класса (некоторые — с разбивкой по языку обучения uz/ru/qr) | `KTP_GRID` |
| Устное подтверждение (в переписке) | Какие ЕСП-варианты предмета («по выбору», «Экономика», «Жасорат») подставлять для какого трека/класса | `JASORAT_MAP`, `EKONOMIKA_MAP`, `TRACK_SUBJECT_VARIANTS` |
| Отчёт «Сотрудники» eMaktab (реальный `.xls`) | Формат импорта учителей и классов (только ФИО и колонка «Классы» — ПИНФЛ/дата рождения/телефон/почта намеренно не сохраняются) | `parseStaffExport` |

### 4.1 Правило подстановки часов (`computeOfficialPlan`)

1. Официальные цифры доступны только если `schoolType==="criterial"` и класс 5–11.
2. Без профиля — берётся колонка `base` по номеру класса.
3. Профиль 10-11 класса — колонка трека **полностью заменяет** базовую (не складывается с ней).
4. Название предмета подменяется на вариант ЕСП («по выбору» / «Экономика» / «Жасорат»), но **только если часы трека отличаются от обычных для этого же класса** — если совпадают, предмет остаётся под обычным названием, даже в профильном классе. Направление роста часов определяет вариант: больше обычного → «по выбору», меньше — «Экономика».
5. «Жасорат» (5-6 класс) — предметный набор реальный (из ЕСП), но часы официально не описаны нигде: берутся как в обычной сетке, с явной пометкой «часы не официальные».
6. Взаимоисключающие альтернативы (родной язык по языку обучения, выбор 1-го/2-го иностранного, разбивка «Технологии» на группы) помечены в `KTP_GRID` полями `langGroup` / `choiceGroup` / `techVariant` и фильтруются по параметрам класса.

## 5. Функциональные модули (вкладки)

1. **Классы и смены** — глобальные параметры недели + тип школы; на класс — параллель, число учеников, язык обучения, специализация (Жасорат/трек).
2. **Предметы** — общий справочник, у каждого предмета: обязательный тип кабинета (свободный текст, сверяется с «Кабинетами») и флаг «тяжёлый» (задел под будущую мягкую оптимизацию).
3. **Учителя** — вручную или импортом реального отчёта eMaktab; предметы, макс. уроков/день, выходные дни.
4. **Кабинеты** — название, вместимость, тип.
5. **Учебный план** — при первом открытии для критериальной школы 5–11 класса план заполняется автоматически из `KTP_GRID`; при смене параллели/языка/трека/технологии — план помечается неактуальным и перезаполняется при следующем открытии. Полностью доступен и ручной режим (для классической школы и 1–4 класса). На уровне предмета — блок (обычный/сдвоенный/строенный) и связь с другим предметом для группового урока.
6. **Расписание** — генерация, ручная правка ячейки (выбор из «юнитов» — одиночных или групповых уроков), блокировка ячейки, просмотр по классу и по учителю, таблица соответствия часов плану.
7. **Экспорт** — Excel (по листу на класс + на учителя + сводный по кабинетам, если заведены), JSON-бэкап настроек школы, сброс.

## 6. Движок генерации расписания

Жёсткие ограничения (модель по образцу edarsjadval.uz, без their OR-Tools — реализовано как рандомизированный жадный алгоритм с несколькими попытками):

- **Конфликты** — учитель/класс/кабинет не в двух местах одновременно.
- **Вместимость и тип кабинета** — предмет с заданным `roomType` ищет кабинет этого типа с вместимостью ≥ числа учеников класса; если кабинетов вообще не заведено — проверка вместимости отключается целиком.
- **Групповые уроки** (`syncWith`) — два предмета одного класса, связанные друг с другом, всегда ставятся **в один и тот же слот**, разными учителями (решает проблему «Технология: мальчики/девочки», которую отдельные предметы с независимой расстановкой решить не могут).
- **Сдвоенные/строенные уроки** (`blockSize`) — блок из 2-3 уроков подряд в один день, не разбивается перерывом.
- **Блокировка ячейки** — при повторной генерации заблокированные уроки не трогаются, вокруг них перестраивается остальное.

Алгоритм (`tryBuildOnce`): для каждого класса строится список «юнитов» (`computeUnits` — одиночный предмет или связанная пара), сортируется по убыванию часов, каждый юнит распределяется по дням (балансировка нагрузки) и слотам со случайным перебором; 40 попыток с разными seed, выбирается лучшая по числу неразмещённых уроков.

**Предгенерационная проверка (`validateBeforeGenerate`):** пустой план, предмет без учителя, несовпадение часов в групповой паре, отсутствие кабинета нужного типа, превышение недельной нагрузки учителя.

## 7. Явные упрощения и известные ограничения

Раздел ведётся честно — чтобы следующий разработчик не тратил время на повторное обнаружение того же самого:

- **Нет А/Б чередования недель** (edarsjadval.uz это поддерживает).
- **Нет мягкой педагогической оптимизации** — 8 критериев конкурента (нет «окна» у класса, распределение предмета по неделе, дистанция между повторами, отсутствие соседних одинаковых уроков, баланс дневной нагрузки, тяжёлые предметы не подряд, окна учителя, усталость/выходной) пока не реализованы; движок жадный, а не оптимизирующий.
- **Preflight-диагностика** заметно проще, чем «28 типов проблем» у конкурента — сейчас 5 категорий проверок.
- **Нет PDF-экспорта** — только Excel.
- **«Технология: мальчики/девочки»** технически решается групповым уроком, но это два предмета-заглушки (`Технология (мальчики)` / `(девочки)`) без единого ID ЕСП — в реальном справочнике это один и тот же предмет «Технология»; для интеграции с ЕРП это может потребовать доп. маппинга.
- **Новая категория предметов «вариатив»** (добавлена в справочник версией 1.10, 21 сентября) заведена в каталог предметов, но **не встроена** в автозаполнение учебного плана — неизвестно, к какому классу/треку она относится.
- **Интеграция с eMaktab отсутствует принципиально** — не запланирована и не будет реализована (осознанное решение продукта, не техническое ограничение).

## 8. Приватность

При импорте отчёта «Сотрудники» из eMaktab сохраняются только ФИО и колонка «Классы» (для автообнаружения реальных классов школы). ПИНФЛ, дата рождения, телефон и электронная почта — **не читаются и не сохраняются** ни в `state`, ни в `localStorage`, ни в экспортируемых файлах.
