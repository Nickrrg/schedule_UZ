# Конструктор расписания — ТЗ: функциональные требования и этапы

**Версия:** 1.7 · **Дата:** 2026-10-03 · **Код:** v0.12.0 (новая структура интерфейса — ФТ-22; правила школы и доступность учителей — ФТ-18, перенос в eMaktab — ФТ-19, приказ №133 — ФТ-20, помощник и конструктор на разных экранах — ФТ-21; пилот: загрузка из eMaktab — ФТ-16, проверка — ФТ-17, сквозная нумерация уроков — ФТ-2.4, ФТ-2.6)
**Связанные документы:**
- `ARCHITECTURE.md` — архитектурные решения (ADR-1…ADR-11);
- `ПМИ_конструктор_расписания.md` — программа и методика испытаний;
- `Техническое_описание.md` — как устроен код сейчас (модель данных, алгоритмы, хранение, выпуск);
- `План_доработок.md` — дорожная карта; `Пилот_импорт_eMaktab.md` — пилот;
- `../README.md` — как устроен код.

Этот документ заменяет ТЗ v0.6 (`ТЗ_и_архитектура_конструктор_расписания.md`): его содержание вошло в Части I и III.

**Как читать.**
- **Часть I** — полный набор функций продукта и то, *как* каждая работает: поля, допустимые значения, значения по умолчанию, правила, реакция системы. Описание сверено с кодом `index.html` v0.6.
- **Часть III** — справочная информация: рынок, источники нормативных данных, сверка с реальными расписаниями, модель данных v0.6.
- **Часть II** — этапы: что из Части I делается в каком этапе, критерии приёмки этапа.

**Статус требования** (колонка «Ст.»):
- **есть** — реализовано в v0.6 и работает так, как описано; при переработке кода поведение сохраняется;
- **изм** — реализовано, но в пилоте поведение меняется на описанное (текущее поведение указано явно);
- **П** — новое, делается в этапе 1 (пилот);
- **И** — новое, этап 2 (интеграция);
- **Б** — бэклог (этап 3).

**Термины.**
- *Параллель* — все классы одного года обучения (1…11).
- *ДО* — класс домашнего обучения.
- *Слот* — одна позиция урока в дне на общей оси школы; с 0.10 слот = номер урока школы (см. ФТ-2.6).
- *Юнит* — одна размещаемая единица учебного плана: обычный урок или групповой урок из двух связанных предметов.
- *Критериальная / классическая школа* — тип школы, от которого зависит наличие официальной сетки часов.

### ФТ-2.4 Сквозная нумерация уроков и звонки школы (0.10)
В eMaktab уроки нумеруются по всей школе: вторая смена продолжает номера (уроки 8–12), смены могут перекрываться (6-A — уроки 4–10, 5-B — 1–6). С 0.10 модель конструктора такая же — «смены» как настройки больше нет.

| ID | Требование | Ст. |
|---|---|---|
| ФТ-2.4.1 | У параллели и класса вместо «Смены» — «С урока» (ФТ-2.2.2, ФТ-2.3): класс занимает уроки школы с «С урока» по «С урока + уроков в день − 1». В сетке класса строки подписаны номерами уроков школы («1-A — расписание (уроки 7–11)»); вид «По учителям», листы Excel, шахматка и печать — по урокам школы 1…N. На экране «Классы и режим» — «Уроки школы: 1–N». | есть (0.10) |
| ФТ-2.4.2 | Учитель и кабинет — одни на всю школу: урок с одним номером у двух классов — это одно и то же время, в т.ч. при перекрытии смен. Генератор такие конфликты не создаёт, проверка (ФТ-17) их показывает. | есть (0.10) |
| ФТ-2.4.3 | **Звонки школы** по номерам уроков: карточка «Звонки» на шаге «Классы и режим» — «Задать время уроков» (08:00, урок 45 мин, перемена 10, большая перемена 20 мин после 3-го урока), правятся начало, длительность урока, перемены, номер урока перед большой переменой и её длина; ниже — расчёт «1. 08:00–08:45 · 2. …» для всех уроков школы; «Убрать звонки». # Часть II. Этапы

| Этап | Цель | Состав | Оценка |
|---|---|---|---|
| **1. Пилот** | Завучи пилотных школ сами, без помощи разработчиков, получают бесконфликтное расписание и выгружают его; мы измеряем, где они отваливаются | Все требования **есть** (сохранить) + **изм** + **П**; дефекты Д-1…Д-12; технический фундамент | 6–9 нед |

**Принятое ограничение:** данные привязаны к браузеру; на другой компьютер — переносом файла.

## III.3 Сверка с реальными расписаниями школ

Проверено на реальных выгрузках eMaktab: 44 класса 1–11 параллелей (одна неделя) и одна параллель за всю четверть (10 недель).

**Подтвердилось:**
- групповые уроки с разными учителями — частый случай (языки, информатика, физкультура, технология), поэтому групповой урок сделан общим механизмом (ФТ-6.3);
- найдено 9 настоящих случаев, когда учитель назначен в два класса одновременно, — проверка конфликтов решает реальную проблему.

**Привело к доработкам (сделано в v0.6):** разная длина недели по параллелям, домашнее обучение, уроки без учителя, дробные часы из приказа №183, три смены, разное число уроков в день у параллелей.

**Под вопросом:**
- в выгрузке за четверть недели 6–9 заполнены заметно скуднее. Рабочая гипотеза — завуч не доделал расписание вперёд, а не особенность системы. Многонедельная сетка не строится (ФТ-9.10);
- один и тот же учитель иногда числится одновременно в обеих группах разделённого предмета — реальная накладка или особенность журнала (открытый вопрос 6).

## III.4 Модель данных v0.6

> **Актуальная модель данных (схема 3, v0.10) — `Техническое_описание.md`, раздел 3.** Ниже — исторический формат v0.6 для справки.

> С v0.7.0 у класса добавились поля `variativ` (направление №227), `qardoshSample` (образец 1/2), `appliedPlan` (по какому документу заполнен план), используется `periodsOverride`; у предмета — `nameUz`. Целевая модель — `ARCHITECTURE.md`, ADR-3.

Текущий формат данных в коде. Целевой формат (UUID, версия формата, ID школы, расписание отдельной версией) — `ARCHITECTURE.md`, ADR-3.

```
state = {
  config: {
    schoolType: "criterial" | "classical",     // единственный параметр уровня школы
    parallels: { [grade 1..11]: { days: 5|6, shift: 1|2|3, periods: number } },
    // устаревшие поля — только запасные значения и миграция старых сохранений:
    days, shifts, periodsPerShift, homeschoolPeriodsPerDay, periodsMigrated
  },
  classes: [{
    id, name, grade: 1..11 | null,
    daysOverride: 5|6|null, shiftOverride: 1|2|3|null, periodsOverride: number|null,  // null — как у параллели
    isHomeschool, studentCount, instructionLang: "uz"|"ru"|"qr",
    jasorat, track, trackLang, firstForeignLang, secondForeignLang,
    technologyMode: "split"|"unified"|"agro", officialPlanApplied
  }],
  subjects: [{ id, name, nameUz, espId, erpId, roomType: string|null, heavy: boolean }],
  teachers: [{ id, name, subjects: [subjectId], maxPerDay, daysOff: [bool × 6], homeroomNote? }],
  rooms:    [{ id, name, capacity, type: string|null }],
  curriculum: { [classId]: { [subjectId]: {
    hours,                 // может быть дробным: 0.5, 1.5
    teacherId: id|null,    // null — урок без учителя
    unofficial, blockSize: 1|2|3, syncWith: subjectId|null
  } } },
  schedule: {
    byClass: { [classId]: [day][period] -> { lessons: [{ subjectId, teacherId, roomId }], locked } | null },
    unplaced: [{ classId, subjectId, teacherId }], unplacedCount
  } | null
}
```
Хранится как `{ idSeq, state }`: `idSeq` — счётчик для генерации ID вида `class12`, `subj40` (в пилоте заменяется на UUID — ФТ-12.5).
