## 1. Почему меняем подход (итог брейншторма: продукт, аналитик, завучи, архитектор)

**Проблема.** Чтобы попробовать конструктор, завучу нужно часами вносить учителей, классы, предметы, нагрузку — а результат ещё придётся вручную переносить в eMaktab. Для пилота такой путь нежизнеспособен.

**Что выяснилось:**
- Расписание у школ **уже есть в eMaktab** — его вносят вручную. Данные можно брать оттуда (раздел 3).
- **Импорта расписания в eMaktab нет.** Пользователь — PM eMaktab: интеграцию сделает, если пилот сработает. До этого обратный перенос — вручную.
- Расписание составляют **на четверть, а то и на её часть**, а не на год. Генератор нужен несколько раз в год; ближайший естественный дедлайн — начало следующей четверти.
- Пилот идёт **сейчас**. Для консьерж-теста пользователь найдёт **2 школы**.
- «Потоки» (межклассные группы eMaktab) в Узбекистане **не используются** — не делаем.

**Новый сценарий пилота** (вместо «составить с нуля»):
1. **Загрузить** из eMaktab две выгрузки: сетку по учителям и учебную нагрузку (раздел 3).
2. **Проверить** текущее расписание: конфликты, окна, перегруз — польза в первые 10 минут, до генерации.
3. **Внести изменения четверти**: часы, смена учителя, выходные, закрепления.
4. **Перестроить с минимумом изменений**: урок остаётся на прежнем месте, если ему ничего не мешает.
5. **Выгрузить изменения** в виде, удобном для ручного ввода в eMaktab (раздел 6).

Ручной ввод — бот «с нуля», ручная нагрузка, справочники — остаётся **запасным путём** и дальше не развивается.

**Метрики пилота** (аналитик): время до первой пользы (цель — меньше 15 минут), доля дошедших до результата с импортом и без, число изменённых ячеек при перестроении (меньше — лучше), убранные конфликты и окна.

## 2. Как устроено расписание в eMaktab (важно для выгрузки обратно)

- **Генератор уроков** («Расписания уроков» → схема): **недельная схема класса**. День недели Пн…Вс × номер урока 1…8 (в выгрузках до 12). В ячейке — предмет / «Весь класс» или «Подгруппа X» / учитель («Aliyeva H.R.») / кабинет («Нет кабинета»). Действия: Опубликовать, Очистить, Переименовать, **Копировать схему**, Удалить, Экспорт, Печать. «Опубликовать» ничего не спрашивает.
- **Массовые операции** (ТЗ «ДН. Массовая замена учителя», `дано/`): «Замена педагога» и «Удаление и отмена уроков» — по учителю, предмету, классу, группе («Кто участвует») и периоду («с даты по дату» или до конца года); с причиной из «Перечня причин» (12 значений: больничный, отпуска, командировка, увольнение, производственная необходимость, другое…). Учебный год — 01.08–31.07. Надомники — группа «Надомн.: Фамилия И.».
- **Нумерация уроков сквозная по школе**: вторая смена продолжает номера (большая школа — уроки 8–12; школа 3 — уроки 5/6–10, звонки 1–10 с 08:00 до 16:30), **смены перекрываются** (у 6-A уроки 4–10, у 5-B — 1–6).

## 4. Находки в данных, которые требуют решений

1. **Названия предметов** в трёх системах: обрезанные в A («Узбекский я...», обрезка ~11 символов + «...»), полные в B («Узбекский язык», «Родной (Рус.) язык», «Наука (Science)»), краткие в C («Рус. язык», «Англ. язык»), иногда другие в D («Узбекский (Гос.) язык», «Начальная Допризывная Подготовка», «Основы Государства и Права»). Узбекские классы — по-узбекски («Ona tili», «O'qish», «Ma'naviyat soati»), апостроф в выгрузке как `&#39;`. Есть предметы вне ЕСП: «Кл. час», «Час будущего», «ОГП», «ИТ».
2. **Группы** — произвольные ярлыки школы: «Узб.яз - 1», «Англ.яз.-2», «Физ-ра - М/Д», «Труд-М/Д», «1-гр», «1 гуруппа», «2-guruh», «Qizlar», «o'g'illar», «малъчик», «Анг(ШБ)», «Узб(ОА)» (инициалы учителя). Толковать не пытаемся: группа = ярлык внутри «класс + предмет»; уроки одного «класс + предмет» в одном слоте с разными ярлыками = групповой урок.
3. **ФИО**: «Абдерахманова Н.М.» и «Абдерахманова Н. М.», обрезка «Шайловбаева Л.Х...», «XUSANOVA M.R.», «Закирова_Шарова И.В.», «Нет учителя». Ключ — без пробелов, точек и регистра; обрезанные — по началу.
4. **Смены**: сквозная нумерация и перекрытие (раздел 2). Наша модель «смена 1, смена 2 подряд, без перекрытия» такие школы описать не может → **изменение модели** (раздел 5.1).
5. **Буквы классов** в реальных школах — любые латинские: A, B, V, G, D, E, J, … (школа 1), A…Z с пропусками (большая школа).
6. **Конфликты в существующих расписаниях** есть (школа 3) — «Проверка расписания» сразу после импорта покажет завучу пользу.
7. **Объединённые уроки**: один учитель, два класса, один кабинет, один слот (6-B + 6-V, «Математика», каб. 66) — возможно, объединение классов, а не ошибка. Уточнить у завучей; в проверке показывать отдельно («возможно, объединённый урок»).

## 5. Доработки импорта (требования)

### 5.1 Модель данных — до импорта
- **Сквозная нумерация уроков, как в eMaktab.** У класса — номер первого урока (по дням), а не «смена»; ось школы — уроки 1…N с общими звонками. Перекрытие смен допустимо. Миграция: смена k → начало = сумма ширин предыдущих смен + 1 (`schemaVersion` 3).
- **Звонки — на всю школу** по номерам уроков (1 → 08:00–08:45 …), а не по сменам; из выгрузки C их можно взять автоматически.
- **Исходные имена из eMaktab** у учителя, класса, предмета, группы и кабинета (`externalRefs` из ADR-8): по ним собирается выгрузка изменений обратно и повторный импорт.
- **Кабинеты** создаются из выгрузки (номер как название); тип и вместимость неизвестны — пусто.

### 5.2 Импорт «Сетка + Нагрузка»
- Два поля файлов с подсказкой, где их взять (пути из раздела 3); можно загрузить и одну сетку — тогда названия предметов остаются обрезанными, со сопоставлением вручную.
- Распознавание формата по содержимому (двоичный или HTML), а не по расширению; кодировка HTML-сущностей; поиск строки заголовков.
- **Предпросмотр**: учителя, классы (параллель — по числу в названии), кабинеты, уроков в неделю, найденные группы; таблица **сопоставления предметов со справочником ЕСП** — автоматически по полному названию и `nameUz`, спорные и новые — на выбор или «создать свой предмет».
- **Что создаётся:** учителя, классы, кабинеты, план каждого класса (часы = число слотов предмета в неделе, у групп — связанные пары с учителем у каждой), назначения учителей, **текущее расписание** как исходная сетка, все ячейки — «из eMaktab».
- **Сверка A и B**: связки, которые есть в нагрузке, но не стоят в сетке, и наоборот — список замечаний.
- **Повторный импорт** (новая неделя или четверть): обновить, а не задвоить — по исходным именам eMaktab.
- Большая школа (188 классов, 6727 уроков) — разбор за 2–3 с, без зависаний интерфейса.
- **Персональные данные**: только ФИО и названия классов, как в импорте «Сотрудников»; в аналитику — только количества (раздел 7).

### 5.3 Проверка расписания (сразу после импорта)
- Учитель в двух классах в один слот — конфликт; при совпадении кабинета — пометка «возможно, объединённый урок».
- Кабинет занят двумя классами; окна у классов; перегруз учителя в день и в неделю; уроки вне дней или звонков класса.
- Сверка часов с официальным планом (если класс сопоставлен с документом) — информативно.

### 5.4 Перестроение с минимумом изменений (новый режим генератора)
- Исходная сетка — «желательная»: урок встаёт на прежнее место, если там ничего не мешает. Двигаются только затронутые изменениями (часы, учитель, выходной, удалённый урок, правило). Закрепления — как сейчас.
- Критерий выбора попытки: неразмещённые → число изменённых ячеек → окна.
- В итогах: «изменено ячеек: N в K классах».

## 6. Выгрузка обратно в eMaktab (ручной перенос)

1. **Схема класса в формате eMaktab** (как D): Пн…Вс × 1…N, в ячейке предмет / «Весь класс» или «Подгруппа X» / учитель / кабинет — исходными именами eMaktab.
2. **Список изменений по классам**: «Копировать схему → исправить → Опубликовать»; по каждому классу — «добавить: Пн 3 — …», «заменить: Ср 1 — … → …», «убрать: Пт 2»; классы без изменений — «без изменений». Отметки «перенесено» и печать.
3. **Смена учителя на весь период** → одна операция «Замена педагога: учитель, предмет, класс, группа, с даты» — отдельным блоком, без правки схем.

## 7. Доработки флоу: мастер и бот

**Мастер** (сейчас: Классы и режим → Нагрузка → Расписание → Выгрузка):
- Новый первый шаг или вход **«Загрузить из eMaktab»** (2 файла) — основной путь. После импорта — сразу «Расписание» с результатами проверки. «Классы и режим» и «Нагрузка» — для правок.
- Шаг «Выгрузка» → «Перенос в eMaktab»: схемы классов, список изменений, замены учителей, печать; Excel — дополнительно.

**Бот** (сейчас 5 экранов: Школа → Режим → Учителя → План → Составить):
- **Экран 1: «Расписание уже есть в eMaktab?»** — «Да, загружу» (основной) / «Нет, начну с нуля» (текущие 5 экранов).
- Ветка «Да»: загрузка сетки и нагрузки → предпросмотр и сопоставление предметов → проверка («нашёл N конфликтов, M окон») → «Что меняем в новой четверти?» (перейти к правкам или сразу перестроить) → итог с переходом к списку изменений.

**Аналитика** (каталог `EVENT_CATALOG`): `import_emaktab_result` (ok, файлы, учителя, классы, уроки, несопоставленные предметы, длительность), `check_result` (конфликты, окна), `rebuild_result` (изменено ячеек), `transfer_list_opened`, `transfer_marked`; веха `imported`. Без ФИО и названий.
