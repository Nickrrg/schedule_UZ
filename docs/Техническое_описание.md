## 1. Что это и как устроено в целом

Конструктор — одна HTML-страница `index.html` (≈ 6 070 строк, ≈ 525 КБ): разметка, стили и весь код в одном `<script>`, синтаксис ES5, без сборки и фреймворка. Сервера нет: данные хранятся в браузере. Страница открывается как файл или с любого статического хостинга.

| Часть | Где | Назначение |
|---|---|---|
| Страница | `index.html` | Мастер из 4 шагов, «Справочники», «Из eMaktab», бот, генератор, проверка, выгрузки |
| Внешняя библиотека | `xlsx-js-style` 1.2.0 с cdn.jsdelivr.net (SheetJS 0.18.5 с записью стилей) | Чтение выгрузок eMaktab (.xls двоичный и HTML), запись Excel с переносом строк |
| Аналитика | Яндекс.Метрика (номер счётчика не задан) | JS-цели `tt_*` через каталог событий |
| Тесты | `tests/browser/smoke.html` + `smoke.js`; данные — `tests/fixtures/emaktab/` | 168 сквозных проверок в браузере |
| Инструменты | `tools/npa/` — учебные планы из PDF приказов; `tools/emaktab/` — анализ выгрузок eMaktab | Генерация нормативных данных, исследование форматов |
| Реальные данные | `дано/` (ФИО учителей) | Только локально, **в репозиторий не загружать** |
| Версии | `_релизы/<версия>/` — снимки; `_загрузка/<дата>_<версия>/` — наборы изменённых файлов для GitHub | Выпуск вручную (git локально нет) |

### Жизненный цикл страницы
1. Загрузка: `loadState()` читает `localStorage["timetable_builder_v4"]` → `ensureParallels()` → `ensureCatalog()` + `migrateSchema()` (цепочка версий схемы) → `sanitizeSchedule()`.
2. `render()`: выбирает шаблон шага (`tpl*()`), строит HTML строкой, вставляет в `#main`, обновляет степпер, бота, шапку; в конце `saveState()` (пишет, только если данные изменились).
3. События — делегирование: `onClick` / `onChange` на `#main` по атрибуту `data-act`; бот — `data-bot-act`; загрузка eMaktab — `data-emk-act` / `data-emk-file` / `data-emk-map` на `document`; импорт «Сотрудников» — `data-imp-act`.
4. Любая правка данных, влияющая на расписание, вызывает `invalidateSchedule(причина)`: расписание не стирается, помечается «устарело», убираются только ставшие невозможными ячейки.

## 3. Модель данных (схема 3)

Всё состояние — объект `state`, в `localStorage` лежит `{ idSeq, state }`. Идентификаторы — `uid(prefix)` на счётчике `idSeq` (UUID — план фазы 0, ARCHITECTURE ADR-3).

```text
state
├ schemaVersion: 3                   // цепочка миграций migrateSchema()
├ schoolId: UUID                     // tenant на будущее
├ config
│  ├ schoolType: "criterial" | "classical"
│  ├ parallels[1..11]: { days: 5|6, start: 1..14, periods: 3..10, periodsByDay: [Пн..Сб] | null }
│  ├ schoolBells: { start "08:00", len, brk, bigAfter, bigLen } | null      // звонки школы
│  └ homeschoolPeriodsPerDay, periodsMigrated, …                           // наследие
├ classes[]: { id, name "5-A", grade 1..11|null, instructionLang uz|ru|qr|kz|kg|tj|tm,
│              daysOverride, startOverride, periodsOverride, periodsByDay,   // значение класса → параллели → запасное
│              isHomeschool, studentCount, jasorat, track, variativ, firstForeignLang, secondForeignLang,
│              technologyMode, qardoshSample, officialPlanApplied, appliedPlan{…},
│              ext{ emaktab: "10-E" }, langGuessed, directionAsked }         // три последних — с 0.10
├ subjects[]: { id, name, nameUz, espId, erpId, roomType, heavy, notPeriods[], fixedSlot{day, period} }
├ teachers[]: { id, name, subjects[], maxPerDay|null, daysOff[6], homeroomNote, ext{ emaktab } }
├ rooms[]: { id, name, capacity|null, type|null, ext{ emaktab } }
├ curriculum[classId][subjectId]: { hours, teacherId, blockSize 1..3, syncWith subjectId|null, groupSize,
│                                   unofficial, ext{ subject, group } }      // ext — строка из eMaktab
├ schedule | null
│  ├ byClass[classId][day][p]: { lessons: [{ subjectId, teacherId, roomId }], locked, manual, src: "emaktab" } | null
│  │                                   // p — урок класса с 0; урок школы = start + p
│  ├ unplaced[]: { classId, subjectId, teacherId, reason{code, teacherId} }, unplacedCount, windows
│  ├ generatedAt | null, importedAt, source: "emaktab" | —, stale, removedSinceGen, exportedAt
└ emaktab | undefined                  // с 0.10, после загрузки
   ├ importedAt, week "пн, 14 сент. — вс, 20 сент.", grid, load   // имена файлов
   ├ subjectMap: { "Англ. язык": subjectId, … }                   // сопоставление запоминается
   └ base: [[classId, day, lessonNo, subjectId, teacherId, roomId], …]   // исходная сетка для списка изменений
```

**Групповой урок** — две строки плана, связанные `syncWith`: «Английский язык» и «Английский язык (группа 2)»; генератор ставит их в один урок. Юнит (`computeUnits`) — одна размещаемая единица: обычный урок или пара групп.

**Ось слотов** (ФТ-2.6): слот = номер урока школы − 1. Класс занимает слоты `start−1 … start−1+уроков−1`; занятость учителей и кабинетов — по слотам всей школы, поэтому перекрывающиеся смены обрабатываются естественно.

### Миграции (`migrateSchema`)
| Версия | Что делает |
|---|---|
| 1 → 2 (0.9) | у учителя — `daysOff`, `subjects`; появляется `schoolId` |
| 2 → 3 (0.10) | `migrateShiftsToLessons()`: смена k → `start` = сумма ширин предыдущих смен + 1 (ширина — наибольшее число уроков у классов смены), смена класса-исключения → `startOverride`; звонки 1-й смены → `schoolBells`; названия «6-А» (кириллица) → «6-A» |
| без версии | `ensureParallels()` (параллели и значения по умолчанию), `ensureCatalog()` (долив справочника ЕСП по названию), `migrateLegacySubjects()` (переименования) |

### Ключи `localStorage`
`timetable_builder_v4` (данные), `timetable_builder_v4_corrupt` (отложенная нечитаемая копия), `timetable_builder_tab` (другая вкладка), `timetable_builder_lang` (язык интерфейса), `tt_bot` (шаг и путь бота), `tt_install_id`, `tt_school` (аналитика).

## 4. Основные алгоритмы

### 4.1 Генератор (ФТ-8)
Жадная расстановка юнитов: 40 попыток с разным зерном (`mulberry32`), выбирается попытка с меньшим числом неразмещённых, при равенстве — с меньшим числом окон. Учитывает: занятость класса, учителя (все слоты школы, выходные, максимум в день), кабинета (тип, вместимость по размеру группы, у групп — разные кабинеты), блоки (сдвоенные уроки подряд), правила предметов («не на уроках», «всегда день и урок»), закреплённые ячейки. У неразмещённого урока — причина (`teacher_busy`, `teacher_off`, `no_room`, `rule`…). Результат без окон ставится с первого урока класса.

### 4.2 Загрузка из eMaktab (ФТ-16)
1. **Чтение**: `XLSX.read` любого файла → `emkDetect` по содержимому: сетка (строка «Учитель» с номерами уроков), нагрузка («Предмет» + «Количество часов»); «Сотрудники», расписание класса, схема генератора — понятное сообщение.
2. **Разбор сетки**: колонки — день (объединённые ячейки) × номер урока; ячейка — блоки по 3 строки «Предмет / Класс (группа) / Кабинет». Текст HTML-сущностей декодируется (`emkDec`).
3. **Полные названия** из нагрузки: у того же учителя (ключ ФИО без пробелов и точек) и класса — предмет, начинающийся с обрезанного названия сетки.
4. **Предпросмотр** (`emkBuild`): учителя (обрезанные ФИО — по началу), классы и диапазоны уроков, кабинеты, группы; замечания: неполная неделя, воскресенье, нулевой урок; сверка сетки и нагрузки — замены (предмет в классе ведёт другой учитель) и разовые уроки (меньше половины «уроков за период на 1 час в неделю», медиана по совпавшим связкам) скрываются.
5. **Сопоставление предметов** (`emkMatchSubject`): запомненное → дословно по `name`/`nameUz` (включая предметы по направлению) → короткие и кириллические узбекские названия ЕСП (`EMK_ESP_NAMES`, 97) → синонимы eMaktab (`EMK_SUBJECT_ALIASES`) → по началу обрезанного → «новый».
6. **Перенос** (`emkApply`): учителя, кабинеты, классы (дни, `start`, уроки по дням; общее для параллели — в параллель, отличия — у класса), язык класса по предметам, план (часы = уроки в неделю; группы → пары «предмет (группа N)», связываются, если всегда в одном уроке), исходная сетка с `src: "emaktab"` и снимок `emaktab.base`. Повторная загрузка сопоставляет сущности по `ext.emaktab` и сохраняет их id и настройки.

Производительность (реальные данные): школа 50 классов / 1 731 урок — 0,4 с; 188 классов / 6 727 уроков, нагрузка 6 МБ — разбор ≈ 2 с, перенос ≈ 0,5 с, сохранение ≈ 1,5 МБ.

### 4.3 Проверка расписания (ФТ-17)
`checkSchedule()` за один проход по сетке: учитель в двух классах в одном слоте (если кабинет у всех один — «возможно, объединённый урок»); кабинет у двух классов при разных учителях (кроме спортзала и т. п., `checkSharedRoom`), сгруппировано по кабинетам; два разных урока в ячейке (не группы); окна (`rowWindows`, как в итогах генерации); урок в выходной; перегруз при заданном максимуме. Плюс рекомендации: `planDiff()` по каждому классу 5–11 и `suggestDirection()`.

### 4.4 Сверка с планом и направление (ФТ-17.4–17.5)
- Ключ сверки `planKey()`: без «(группа N)» и вариантов технологии; «Государственный язык (узбекский)» = «Узбекский язык»; в русских классах «Русский язык» из eMaktab = «Родной язык» плана (`planReconcile`). Дробные часы плана — норма при 0 или 1 в неделе. Предметы вне справочника ЕСП не сверяются.
- Направление: если у класса без направления есть предметы «… по выбору / вариатив / Экономика / Жасорат / как второй иностранный язык», перебираются допустимые направления (`directionCandidates`: Жасорат 5–6, №227 7–11, №183 10–11 в критериальной школе), план считается с временно подменёнными параметрами класса (`officialNeedWith`), выбирается направление с наименьшим расхождением, если оно меньше, чем с базовым планом, — и задаётся вопрос завучу.

### 4.5 Excel (ФТ-10)
`buildWorkbook()`: лист «Все классы» (день × урок школы × классы), лист на класс, лист на учителя, «Кабинеты». `xlsxFitSheet()` задаёт каждому листу ширины колонок (по самой длинной строке, 6…40 знаков), перенос строк и выравнивание по верху во всех ячейках, высоту строк по числу строк текста, жирную первую строку.

## 5. Аналитика и персональные данные
- Каталог `EVENT_CATALOG` — единственный список событий; параметры вне списка отбрасываются, строковые значения — только коды (`[A-Za-z0-9_:.,-]`), поэтому ФИО и названия не попадают в события (автотест T-13-02). Ко всем событиям — `lang`, `app_version`, `install_id`, `school` (из `?school=`).
- События пилота: `import_emaktab_result`, `check_result`, веха `imported` — только количества.
- Персональные данные: из выгрузок сохраняются ФИО учителей и названия классов, предметов, кабинетов — только в браузере. Реальные выгрузки в репозиторий не кладутся; для тестов — обезличенные копии (ФИО → «Учитель001 А.Б.», проверено отсутствие всех 80 фамилий).

## 6. Локализация
Три механизма: `t(key)` + `STRINGS` — постоянные подписи; `uzt("русская строка")` + `UZ_TR` (словари `UZ_TR`, `UZ_TR_P0`, `UZ_TR_P1`, `UZ_TR_P2`) — строки в разметке; `nameUz` у предмета — названия предметов. Автотест: в узбекском интерфейсе нет кириллицы (кроме данных школы). Перевод строк P1 и пилота сделан без носителя языка — нужна вычитка.

## 7. Тестирование
- `tests/browser/smoke.html` через локальный сервер (`py tools/npa/devserver.py` → `http://localhost:8766/tests/browser/smoke.html`), кнопка «Запустить»: страница открывается во фрейме, сценарии нажимают кнопки как пользователь и сверяют данные в `localStorage`. На 0.10 — **168 проверок**, все PASS. Тесты очищают `localStorage` этого адреса.
- Сценарии и ID — ПМИ (`T-E-*` — пилот, `T-2-26` — нумерация уроков, `T-11-20` — бот с eMaktab, `T-10-12` — оформление Excel).
- Ручные проверки (Р): большая школа (188 классов), Excel в Excel/LibreOffice, две вкладки, Edge/Safari, печать A4.

## 8. Выпуск версии (сейчас — вручную)
1. Все проверки smoke — PASS.
2. `APP_VERSION` в `index.html`, запись в `CHANGELOG.md`, статус в `README.md` и `План_доработок.md`.
3. Снимок: `_релизы/v<версия>/` (index.html, docs, tests, tools без `out/`).
4. Набор для GitHub: `_загрузка/<дата>_v<версия>/` — изменённые файлы относительно прошлой версии. **Не включать `дано/`** и `tools/npa/out/`.
5. Пользователь загружает набор в `Nickrrg/schedule_UZ` через сайт GitHub.

## 9. Ограничения и технический долг
| Что | Последствие | План |
|---|---|---|
| Один файл, ES5, глобальный `state` | Правка движка может задеть UI; тесты только сквозные | Фаза 1 ARCHITECTURE: `core/` на TypeScript, Vitest |
| Нет git локально, выпуск вручную | Нет истории и отката по коммитам | Фаза 0 |
| ID на счётчике, не UUID | Нельзя слить данные разных источников, связать с eMaktab по id | Фаза 0; пока связь с eMaktab — по именам (`ext.emaktab`) |
| Хранение — `localStorage` (~5 МБ) | Большая школа занимает ≈ 1,5 МБ; две большие школы в одном браузере не поместятся | Фаза 2: IndexedDB |
| Генератор в основном потоке | Большая школа может подвиснуть на секунды при составлении | Фаза 1: Web Worker (ADR-5) |
| Библиотека Excel с CDN | Без интернета нет загрузки и выгрузки | НФТ-2: класть рядом со страницей |
| Правила «синонимы предметов», «равные предметы плана» — в коде | Новые названия eMaktab требуют правки кода | Вынести в пакет справочников (ADR-4) |
| Язык класса и направление после загрузки угадываются | Возможны ошибки | Вопрос завучу (направление), язык правится на шаге «Классы и режим» |
