## 1. Кто это и что обещает

- Веб-сервис для составления расписания школ Узбекистана. На сайте висит «TEST REJIMI» — бета, бесплатно, нужна регистрация. Есть Telegram-группа и канал, статьи-инструкции для поиска в Google.
- **Главное обещание:** «составит сам за 1–2 минуты». Решатель Google OR-Tools CP-SAT на сервере, «1500+ уроков за 60–90 с», «0 конфликтов — гарантия».
- **Жёсткие правила (6):** нет накладок учителя, кабинета и класса; вместимость и тип кабинета; доступность учителя, класса, кабинета и предмета по «день × урок»; группы идут одновременно; недели А/Б; сдвоенные и строенные уроки.
- **Мягкие правила (13, с весами):** нет окон у класса (самое важное), предмет раскидан по неделе, между уроками предмета есть промежуток, предмет не идёт подряд, ровная нагрузка по дням, трудные предметы не подряд, **нет окон у учителей**, меньше рабочих дней у учителя.
- **Проверка до составления:** «7 проверок, 28 видов проблем» — говорит, почему расписание не получится.
- **Ручная правка:** перетаскивание с проверкой накладок, замок, пересоставление с сохранением закреплённого.
- **Отчёт о качестве:** конфликты, окна учителей, трудные предметы утром (%), занятость кабинетов (%).
- Excel-импорт (по **своему** шаблону), Excel и PDF на выходе, смены и звонки, 6 языков интерфейса.
- **«Интеграция с emaktab.uz — скоро»:** забирать учителей, классы и предметы, загружать готовое расписание, синхронизировать изменения. Пока — «перенесите вручную из PDF или Excel».

## 2. Как устроено приложение (по скриншотам)

Разделы в левом меню: Школа → Классы → Учителя → Предметы → Кабинеты → Уроки → Расписания. Сначала вводят справочники, потом составляют.

| Экран | Что есть |
|---|---|
| Школа | Название, рабочие дни (Пн–Вс), смены с диапазоном уроков (1–7, 8–14), время уроков и перемен, перетаскивание строк |
| Классы | Таблица: класс, классный руководитель, доступное время; «Массовое создание»; фильтр по сменам |
| Учителя | ФИО и короткое имя, предметы, сетка доступности «день × урок» по сменам (зелёные ячейки, «Отметить все» / «Очистить») |
| Предметы | «Готовые наборы» с кодами (MAT, FIZ, ENG) и фильтром по группам предметов |
| Кабинеты | Название, короткое имя, тип, доступность |
| Уроки | Счётчики «уроков / часов в неделю / не завершено»; вкладки «Классы / Учителя / Предметы / Кабинеты»; «Из распределения» (Excel-шаблон по числу классов в параллели: только A / A–B / A–V), «Массовый ввод», «Матрица»; добавление урока — боковая панель (классы, предмет, длительность, часы, учитель, кабинеты, деление на группы) |
| Расписания | Список расписаний с названием («1-й семестр 2024»); при создании — 8 карточек правил с галочками («8/8 активно»), кнопка «Проверить систему (Preflight)» |
| Везде | Справа постоянная панель «Советы», внизу — чат |

## 3. Сильные стороны (что стоит взять)

1. **Обещание «составит сам»** попадает в главную фразу завуча: «Если сама составляет — вот это да».
2. **Качество в цифрах**: окна учителей, итоговая оценка. Завуч видит, стало лучше или хуже.
3. **Окна учителей** — считаются и уменьшаются. У нас — только окна классов.
4. **Перетаскивание с мгновенной проверкой** и замок + пересоставление.
5. **Проверка до составления** с причинами — маркетинг построен вокруг неё.
6. Мелочи интерфейса: пустые экраны с двумя кнопками, счётчики в шапке, сетка доступности с «Отметить все», готовый набор предметов, правила карточками с галочками.
7. Поддержка: Telegram-группа, статьи. Сезон короткий — быстрый ответ ценен.

## 4. Слабые стороны (где мы сильнее)

1. **Начинают с пустого листа.** Завучу надо ввести школу, классы, учителей, предметы, кабинеты, уроки — ровно то, от чего мы ушли в пилоте (`Пилот_импорт_eMaktab.md`, §1). Их Excel — собственный шаблон, а не выгрузка eMaktab.
2. **Нет работы с текущим расписанием**: нельзя загрузить то, что уже есть в eMaktab, проверить его, получить список изменений для переноса. Пересоставление — только «с замками», без «меньше всего изменений относительно eMaktab».
3. **Нет норм Узбекистана**: Kelajak soati Пн-1, методические дни, план по приказу №133, сверка с планом — у них общие «педагогические» правила.
4. **Язык и слова**: на одном экране узбекский и русский вперемешку («Yangi o'qituvchi», «Sahifada», «Qo'shish» в русском интерфейсе), заголовки с резервным шрифтом с засечками, слова «Preflight», «Multi-Shift», «Матрица», «Блокировка». Для завуча, который боится компьютера, — барьер.
5. **Регистрация** до первого результата. Мелкие ошибки: в поле «Название школы» — имя пользователя.
6. **Интеграция с eMaktab зависит от eMaktab.** Мы и есть eMaktab — это наше главное преимущество и их главный риск.

## 5. Выводы с разных сторон

**Продукт.** Конкурент продаёт «составит сам», мы — «проверит и поможет перенести». Проверка — не риск: пользователь (2026-09-29) считает её хорошей функцией на весь год. Дополнительно — не догонять их по числу функций, а показать **составление поверх расписания из eMaktab**: «Улучшим ваше расписание: окна у классов было 34 → стало 6, в eMaktab поменять 41 ячейку в 12 классах». Перестроение с минимумом изменений становится главной функцией пилота, а не следующей по списку.

**UX.** Их путь — «сначала справочники». Наш — «загрузил из eMaktab → увидел проблемы → улучшил → перенёс». Путь не менять. Взять: цифры качества «было → стало», перетаскивание с подсветкой, правила карточками. Не брать: семь разделов меню, постоянную панель советов справа, 13 весов, английские слова.

**UI.** Оформление у них аккуратное, но смешанный язык и шрифты выдают сырость. Нам важнее единый язык экрана и крупные понятные цифры. Остаёмся в стиле eMaktab (светлая тема, синие рамки, Inter).

**Архитектор.** CP-SAT на сервере — правильное направление после пилота (у нас фаза 6, «серверный решатель»). OR-Tools бесплатен (Apache 2.0), сервер — на стороне eMaktab. В пилоте оставляем браузерный генератор, но делаем так, чтобы потом решатель можно было заменить: одна функция «составить (данные, правила, закреплённое, исходное расписание) → расписание + оценка качества». «Минимум изменений» и «окна учителей» описываем как штрафы — это прямо переносится в CP-SAT. Оценку качества считаем одной функцией и для проверки, и для итога генерации.

**Аналитик.** Добавить к событиям: время составления, число неразмещённых, окна классов и учителей до и после, число изменённых ячеек, дошёл ли до «перенесено». Метрика успеха пилота: доля школ, где «было → стало» лучше и изменения перенесены в eMaktab.
