# Как тестировался код (нет в CI, для справки)

Готовых тестовых файлов в репозитории нет — они писались по одному, под каждую конкретную правку, в scratch-окружении вне репозитория, и не сохранялись. Это стоит исправить: следующая правка движка или модели данных должна класть свой сценарий сюда, а не терять его.

## Способ

1. Из `index.html` вырезается содержимое `<script>...</script>`.
2. В конце, вместо строк
   ```js
   render();
   initCloudSync();
   })();
   ```
   подставляется
   ```js
   global.__test = { state: function(){ return state; }, generateSchedule, computeUnits, /* + всё, что нужно проверить */ };
   })();
   ```
   — то есть наружу пробрасывается то, что нужно тесту, вместо запуска приложения.
3. Перед запуском в Node нужна минимальная заглушка `document`/`localStorage`/`XLSX`/`claude`/`URL`/`Blob`, чтобы код, писавшийся для браузера, не падал при загрузке. Ключевое: у заглушки `document.getElementById` должен возвращать **один и тот же** объект при повторном вызове с одним и тем же id (простой кэш по id) — иначе не поймать баги вида «обработчик событий вешается заново при каждой перерисовке» (такой баг был найден именно так).
4. Дальше — обычный `node script.js` с `console.log(condition ? "PASS" : "FAIL", "описание")` на каждую проверку.

## Что проверялось на этот код (ориентир для новых сценариев)

- **Дни/смена/уроки по классу**: наследование от параллели, переопределение у класса, ось слотов (`slotLayout`) при разной ширине смен, класс на домашнем обучении после всех смен, миграция старых сохранений (было общешкольное значение → стало у параллели).
- **Групповые уроки** (`syncWith`): всегда один и тот же слот, разные учителя; сдвоенные/строенные блоки (`blockSize`) занимают подряд идущие слоты в один день.
- **Кабинеты**: урок с заданным типом кабинета встаёт только в кабинет этого типа и подходящей вместимости; без заведённых кабинетов проверка не мешает генерации.
- **Дробные часы** (0.5, 1.5): округление вверх до целого слота при расстановке, исходное значение остаётся в отчётности.
- **Урок без учителя**: размещается, не участвует в проверке занятости учителя, не блокирует предгенерационную проверку.
- **Справочник предметов**: `ensureCatalog` доливает новые предметы в старые сохранения без дублей и без потери id, уже использованных в планах; `migrateLegacySubjects` переносит план/учителя со старого (переименованного/опечатанного) названия предмета на новое, дублей не остаётся.
- **Бот**: полный проход по всем шагам меняет те же данные, что мастер; изменение числа классов в параллели на повторном проходе добавляет/удаляет классы (с удалением их учебного плана), не трогая классы ДО; текст истории бота пересобирается заново при смене языка интерфейса (а не застывает на языке, на котором был задан вопрос).
- **Локализация**: у каждого ключа `STRINGS`/`BOT_T` есть узбекский перевод; у каждого предмета справочника есть `nameUz`; после рендера всех вкладок, учебных планов нескольких классов (обычный, Жасорат, профиль 10-11, ДО), расписания, экспорта в Excel и диалогов подтверждения в узбекском режиме — ни одной кириллической буквы в собранном HTML/тексте.
- **Регрессия при каждой новой правке**: два сквозных сценария (обычная школа с кабинетом и групповым уроком; 5-дневный класс + ДО + дробные часы + урок без учителя одновременно) прогонялись заново после каждого изменения движка, чтобы поймать, что новая правка не сломала старую.
