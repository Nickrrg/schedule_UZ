# Конструктор расписания — архитектура и техническое задание

**Репозиторий:** https://github.com/Nickrrg/schedule_UZ
**Реализация:** `timetable-builder.html` — один самодостаточный веб-файл.
**Версия:** 0.6

## 1. Назначение

Инструмент для завуча: собрать данные о школе (классы, предметы, учителя, кабинеты, учебный план) и автоматически составить бесконфликтное расписание уроков, с ручной правкой и экспортом в Excel.

Заполнить данные можно двумя способами, результат один и тот же:
- **бот «Быстрая настройка»** — задаёт вопросы кнопками и сам заполняет мастер, для тех, кому так проще;
- **мастер** — 7 шагов, где всё настраивается вручную и подробно.

Отличие от рынка (ProRector — десктоп, результат вручную переносится в eMaktab; edarsjadval.uz — веб, сильный движок на OR-Tools, готовит интеграцию с eMaktab): инструмент рассчитан на работу внутри экосистемы eMaktab, без выгрузки данных на сторону. Интеграция с eMaktab не планируется — это решение продукта, а не техническое ограничение.

## 2. Технологическая архитектура

| Слой | Решение |
|---|---|
| Исполнение | Один HTML-файл, ванильный JS (ES5-совместимый синтаксис), без сборки и фреймворков |
| Хранение | Облачное хранилище платформы (`db`), отдельно для каждого пользователя, плюс `localStorage` браузера как резерв (см. раздел 10) |
| Экспорт в Excel | SheetJS (`xlsx.full.min.js`, CDN cdnjs) |
| Скачивание файлов | capability `downloads`; при недоступности — `Blob` + `<a download>` |
| Импорт | Отчёт «Сотрудники» из eMaktab (`.xls`, фактически HTML) через `DOMParser` |
| Вёрстка | Чистый CSS, шрифт Inter, стиль eMaktab, светлая/тёмная/системная тема, мобильная версия |
| Локализация | Словарь строк RU/UZ и функция `t(key)` (см. раздел 11) |
| Аналитика | Слой `track()` под Яндекс.Метрику, счётчик не подключён (см. раздел 12) |

Опубликованная страница объявляет capabilities `db`, `user`, `downloads`.

## 3. Интерфейс

### 3.1 Дизайн
По референсу eMaktab: светлый фон, голубая рабочая панель со скруглением, белые карточки, синяя основная кнопка. Сверху шапка (название, переключатели языка и темы), под ней бот, под ботом горизонтальный степпер мастера: пройденные шаги зелёные с галочкой, текущий синий, будущие серые.

### 3.2 Мобильная версия
На экранах до 720px:
- степпер прокручивается горизонтально, подпись видна только у текущего шага;
- поля и кнопки растягиваются на всю ширину;
- широкие таблицы прокручиваются внутри своей карточки, страница вбок не уезжает;
- учтены вырезы экрана (safe-area).

## 4. Модель данных (`state`)

```
state = {
  config: {
    schoolType: "criterial"|"classical",   // единственный параметр уровня школы
    parallels: {                           // 1..11
      [grade]: { days: 5|6, shift: 1|2|3, periods: number }
    },
    // устаревшие поля, нужны только как запасное значение и для миграции:
    days, periodsPerShift, homeschoolPeriodsPerDay, shifts, periodsMigrated
  },
  classes: [{
    id, name, grade: 1..11|null,
    daysOverride: 5|6|null,        // null — как у параллели
    shiftOverride: 1|2|3|null,     // null — как у параллели
    periodsOverride: number|null,  // null — как у параллели (у ДО — 3)
    isHomeschool: boolean,
    studentCount, instructionLang: "uz"|"ru"|"qr",
    jasorat, track, trackLang, firstForeignLang, secondForeignLang,
    technologyMode: "split"|"unified"|"agro", officialPlanApplied
  }],
  subjects: [{ id, name, espId, erpId, roomType: string|null, heavy: boolean }],
  teachers: [{ id, name, subjects:[subjId], maxPerDay, daysOff:[bool x 6], homeroomNote? }],
  rooms:    [{ id, name, capacity, type: string|null }],
  curriculum: { [classId]: { [subjectId]: {
    hours,               // может быть дробным (0.5, 1.5)
    teacherId: id|null,  // null — урок без учителя, легитимный случай
    unofficial, blockSize: 1|2|3, syncWith: subjectId|null
  } } },
  schedule: { byClass: { [classId]: [day][period] -> { lessons:[{subjectId,teacherId,roomId}], locked } | null },
              unplaced, unplacedCount }
}
```

### 4.1 Как определяются дни, смена и уроки класса
Для каждого из трёх параметров одно правило: **переопределение у класса → значение параллели → запасное значение**.
- `classDays(cls)` — учебных дней в неделю. По умолчанию 1–4 класс — 5 дней, 5–11 — 6.
- `classShift(cls)` — смена 1, 2 или 3. По умолчанию 1.
- `classPeriods(cls)` — уроков в день. По умолчанию 6, у класса ДО — 3.

Число смен в школе не настраивается, а считается: максимум смены среди обычных классов (`shiftsInUse()`).

### 4.2 Ось слотов дня (`slotLayout()`)
Все классы школы живут на одной числовой оси слотов дня:
- смены идут подряд;
- ширина смены равна числу уроков у самого длинного класса этой смены;
- классы домашнего обучения идут после всех смен, их ширина — по самому длинному классу ДО.

Поэтому класс с 8 уроками в 1-й смене не наезжает на 2-ю. Сетки занятости учителей и кабинетов строятся на 6 дней и на всю ось сразу, так что конфликт учителя между сменами, между 5- и 6-дневными классами и с ДО обнаруживается всегда.

## 6. Учебный план: правила подстановки

1. Официальные часы есть только для критериальной школы, 5–11 класс.
2. Без профиля берётся базовая колонка по номеру класса.
3. Профиль 10–11 класса **заменяет** базовую колонку целиком, а не складывается с ней.
4. Название меняется на вариант ЕСП, только если часы профиля отличаются от обычных: больше обычного → «по выбору», меньше → «Экономика». Если часы совпадают, предмет остаётся под обычным названием.
5. «Жасорат» (5–6 класс): предметный набор реальный, часы берутся из обычной сетки с пометкой «часы не официальные».
6. Взаимоисключающие альтернативы (родной язык по языку обучения, 1-й/2-й иностранный, группы технологии) фильтруются по параметрам класса.
7. **Ручной выбор варианта.** У каждого предмета в плане, для которого в справочнике есть варианты, стоит переключатель: обычный / по выбору / вариатив / Экономика / Жасорат. Часы и учитель при переключении сохраняются. Учитель, ведущий предмет, считается подходящим и для всех его вариантов (`teacherCanTeach`).

Для «вариатив» автоматического правила нет (раздел 15), поэтому вариант выбирает завуч.

## 7. Функциональные модули

### 7.1 Бот «Быстрая настройка»
Сценарный бот над мастером. Пишет в те же данные, что и мастер; интерфейс мастера не меняет. Ответы кнопками, 22 шага:
1. Приветствие и предупреждение, что классы и план будут созданы заново.
2. Критериальная или классическая школа.
3. Число классов в каждой параллели 1–11 (0–6). Классы подгоняются под ответ: недостающие добавляются со следующей буквой, лишние удаляются вместе с учебным планом; классы ДО не затрагиваются.
4. Учебные дни, смена и максимум уроков в день — отдельно для 1–4 и 5–11 классов.
5. Загрузка отчёта «Сотрудники» (можно пропустить).
6. Автозаполнение учебного плана по официальной сетке. Для классической школы — подсказка, что план вводится вручную.
7. Составление расписания. Бот сообщает, сколько уроков не поместилось, и напоминает назначить учителей, если они не назначены.

Бот сворачивается (состояние запоминается), начинается заново, говорит на языке интерфейса. Учителей предметам бот не назначает — это делается в мастере (раздел 15).

### 7.2 Мастер (7 шагов)
1. **Классы и смены.** Параметр школы — только тип. Классы сгруппированы по параллелям. При первом запуске создаётся пресет: 1-A … 11-A. У параллели — учебные дни, смена, уроков в день и кнопка «+ класс»: буква подставляется по порядку A, B, V, G, D, E, J, Z, I…, освободившаяся буква заполняется первой, название можно поправить вручную. У класса — переопределение дней, смены и уроков, флаг ДО, число учеников, язык обучения, специализация. Кнопка «Восстановить пресет» добавляет недостающие параллели.
2. **Предметы.** Справочник по алфавиту с поиском. «Тип кабинета» — заполняется, только если предмет должен идти в особом кабинете; значение должно совпадать с типом на вкладке «Кабинеты», есть подсказка из заведённых типов. «Тяжёлый» — задел на будущее, на генерацию пока не влияет.
3. **Учителя.** Вручную или импортом отчёта eMaktab: предметы, максимум уроков в день, выходные дни.
4. **Кабинеты.** Название, вместимость, тип.
5. **Учебный план.** Автозаполнение для критериальной школы 5–11 класса, ручной режим для остального. У предмета: часы (можно дробные), вариант предмета, учитель, блок (обычный/сдвоенный/строенный), групповой урок и кнопка «Разделить на 2 группы».
6. **Расписание.** Генерация, ручная правка ячейки, блокировка ячейки, просмотр по классу и по учителю, сверка с планом.
7. **Экспорт.** Excel (лист на класс, на учителя, сводный по кабинетам), JSON-бэкап, сброс. Сброс возвращает исходное состояние: пресет классов и полный справочник.

## 8. Движок генерации

Рандомизированный жадный алгоритм, 40 попыток с разными seed, выбирается лучшая по числу неразмещённых уроков. Жёсткие ограничения:
- учитель, класс и кабинет не в двух местах одновременно, по всей оси слотов школы;
- тип и вместимость кабинета (без заведённых кабинетов проверка отключается);
- групповые уроки (`syncWith`) — строго в один слот, разными учителями;
- сдвоенные и строенные уроки — подряд в один день;
- дробные часы округляются вверх до целого слота, дробное значение остаётся в отчётности;
- урок без учителя размещается без проверки занятости учителя;
- дни, смена и число уроков — у каждого класса свои (раздел 4.1);
- заблокированные ячейки при перегенерации не трогаются.

Предгенерационная проверка: пустой план, несовпадение часов в групповой паре, нет кабинета нужного типа, превышение недельной нагрузки учителя. Отсутствие учителя генерацию не блокирует.

## 9. Сверка с реальным расписанием школы

Проверено на реальных выгрузках eMaktab: 44 класса 1–11 параллели (неделя) и одна параллель на всю четверть (10 недель).

**Подтвердилось:**
- групповые уроки с разными учителями — частый паттерн (языки, информатика, физкультура, технология), поэтому `syncWith` сделан общим механизмом;
- найдено 9 настоящих двойных назначений учителя в двух классах одновременно — конфликт-чекер решает реальную проблему.

**Привело к доработкам (сделано):** разная длина недели по параллелям, домашнее обучение, уроки без учителя, дробные часы из приказа №183, три смены, разное число уроков в день у параллелей.

**Под вопросом:** в выгрузке на четверть недели 6–9 заполнены заметно скуднее. Рабочая гипотеза — завуч не доделал расписание вперёд, а не системная особенность. Многонедельная сетка не строится.

## 10. Раздельная работа пользователей

**Требование:** два завуча из разных школ работают полностью раздельно, без пересечения данных.

**Реализовано:**
- при открытии страница узнаёт пользователя (`claude.use("user")`) и хранит его данные в `data/users/<id>/state` облачного хранилища (`db`);
- эту зону платформа держит закрытой для всех остальных, включая владельца страницы;
- изменения сохраняются в облако с задержкой 0,8 с, параллельно пишется копия в `localStorage`.

**Резервный режим.** Если `db` или `user` в этом окне недоступны (страница открыта не залогиненным пользователем организации, или вне claude.ai — например, на GitHub Pages), инструмент работает только с `localStorage`. Тогда данные разделены по браузеру, а не по человеку: два завуча на одном компьютере и в одном браузере увидят общие данные.

**На будущее.** При переходе на собственный бэкенд каждая запись должна иметь обязательную привязку к школе (tenant ID) с первого дня схемы, а проверка принадлежности — жить на уровне доступа к данным, не только в интерфейсе.

## 11. Локализация

Переключатель RU/UZ в шапке, выбор хранится отдельно от данных школы. Язык интерфейса не зависит от языка обучения класса и от названий предметов (они остаются как в справочнике ЕСП).

**Переведено:** шапка, степпер, заголовки всех вкладок, основные кнопки, заголовки таблиц, вкладка «Классы» целиком, вкладка «Предметы», бот.

**Пока только на русском:** пояснения на вкладках «Учителя», «Кабинеты», «Учебный план», «Расписание», «Экспорт», названия профильных треков, тексты предгенерационных проверок и сообщений об ошибках, диалог подтверждения сброса. Непереведённый ключ показывается по-русски.

## 12. Аналитика (Яндекс.Метрика) — отложено

В коде есть слой `track(goal, params)`. События уходят как JS-цели `tt_<имя>`:

| Цель | Когда | Параметры |
|---|---|---|
| `tt_tab_open` | открыта вкладка мастера | `tab` |
| `tt_bot_start`, `tt_bot_step` | старт бота, каждый ответ | `step` |
| `tt_preset_create` | восстановлен пресет | — |
| `tt_parallel_add_class` | «+ класс» | `grade` |
| `tt_autofill_plan` | автозаполнение плана | — |
| `tt_schedule_generate` | составлено расписание | `classes`, `unplaced`, `via` |
| `tt_export_xlsx`, `tt_export_json` | экспорт | — |
| `tt_staff_import` | импорт сотрудников | — |
| `tt_lang_switch` | смена языка | `to` |
| `tt_reset_all` | сброс | — |

Ко всем событиям добавляются `lang` и `app_version`. ФИО и ПИНФЛ не передаются.

**Для подключения нужно:** номер счётчика (вписывается в `METRIKA_COUNTER_ID`), домен размещения, согласие на JS-цели, решение о передаче идентификатора школы. Внутри claude.ai-артефакта Метрика не загрузится — политика безопасности блокирует `mc.yandex.ru`. Работать будет только на своём домене. Без номера счётчика события копятся в памяти страницы (`window.__ttEvents`) и никуда не уходят.

## 13. Тестирование

**Правило:** любое изменение движка и модели данных проверяется логическими тестами до публикации, не только проверкой синтаксиса.

**Как устроено:** код страницы запускается в Node.js на заглушке DOM, тесты вызывают функции напрямую и проверяют результат.

| Набор | Что проверяет |
|---|---|
| Бот, варианты, предметы | полный проход бота, подгонка классов, запись параметров параллелей, автозаполнение, генерация, классическая школа, импорт учителей, узбекский язык бота, варианты предметов и их переключение, сортировка и поиск, отсутствие дублей обработчиков |
| Справочник | долив новых предметов в старые сохранения без дублей и без потери id и планов |
| Уроки в день | наследование и переопределение, ось слотов, ДО, миграция, генерация без конфликтов |
| Смены | 1–3 смены, наследование, миграция, учитель в трёх сменах без конфликтов |
| Пресет и дни | пресет, порядок букв, заполнение пропущенной буквы, дни по параллели, рендер всех вкладок RU/UZ, генерация на реальной сетке |
| Регрессия движка | групповые уроки в одном слоте, кабинеты нужного типа, 5-дневный класс, ДО, дробные часы, урок без учителя |

**Не сделано:** тестовые сценарии пока не лежат в репозитории. Их стоит сохранить туда, чтобы не терять между сессиями разработки.

## 14. Исправленные баги (последние версии)

- Новые версии справочника ЕСП не попадали в уже сохранённые данные — теперь доливаются при загрузке.
- «Стереть всё» удаляло заодно весь справочник предметов — теперь сброс возвращает исходное состояние.
- Обработчик Enter подключался при каждой перерисовке: одно нажатие могло добавить несколько одинаковых предметов или учителей.
- Колонка «Тип кабинета» после локализации называлась просто «Тип».
- Учебные дни, смена и уроки в день были параметрами школы, а не параллели и класса; смен было максимум две.

## 15. Ограничения и открытые вопросы

- **Правило для «вариатив» неизвестно.** Предметы есть в справочнике, выбираются вручную в учебном плане; в автозаполнение не встроены.
- **Приказ №183** не перенесён в код: нет двух дополнительных языков обучения (казахский/киргизский/таджикский/туркменский, два состава).
- **Бот не назначает учителей предметам** — это делается в мастере. Без назначений занятость учителей при генерации не проверяется.
- **Бот пересоздаёт классы** по ответам; ручные правки классов при повторном проходе бота могут потеряться.
- **Нет мягкой педагогической оптимизации** (окна, распределение по неделе, тяжёлые предметы не подряд и др.). Флаг «Тяжёлый» пока не используется.
- **Предгенерационная проверка** проще, чем у конкурента.
- **Нет PDF-экспорта.**
- **«Технология: мальчики/девочки»** — два предмета-заглушки без ID ЕСП; для интеграции с ЕРП может понадобиться маппинг.
- **Многонедельная сетка на четверть** не строится (раздел 9).
- **Открытый вопрос к администратору школы:** один и тот же учитель иногда числится одновременно в обеих группах разделённого предмета — реальная накладка или ярлык журнала.
- **Аналитика** ждёт решения по подключению (раздел 12).
- **Локализация** неполная (раздел 11).

## 16. Приватность

При импорте отчёта «Сотрудники» сохраняются только ФИО и колонка «Классы». ПИНФЛ, дата рождения, телефон и почта не читаются и не сохраняются — ни в данных, ни в хранилище, ни в экспорте, ни в аналитике.
