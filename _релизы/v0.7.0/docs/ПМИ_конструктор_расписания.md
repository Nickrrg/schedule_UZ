**Версия:** 1.0 · **Дата:** 2026-09-26

## 1. Общие положения

### 1.1 Виды испытаний
| Вид | Когда | Кто | Что входит |
|---|---|---|---|
| **Автотесты ядра** (unit) | каждый коммит, в CI | автоматически | тесты с типом **А** — ядро (модель, ось слотов, план, проверки, генератор, миграции) без браузера |
| **Автотесты интерфейса** (e2e) | каждый коммит в основную ветку | автоматически, Playwright | тесты с типом **E** — сценарии в настоящем браузере |
| **Ручные проверки** | перед выпуском версии | тестировщик / продукт | тесты с типом **Р** — то, что дорого или бессмысленно автоматизировать (вид, печать, мобильные) |
| **Приёмка версии** | перед выкладкой на домен eMaktab | продукт | раздел 6 |

### 1.2 Поля тест-кейса
- **ID:** `T-<раздел>-<номер>`, раздел совпадает с ФТ.
- **Тип:** А / E / Р.
- **Ст.** — к какому поведению относится ожидаемый результат:
  - **есть** — проходит на v0.6 и должен продолжать проходить;
  - **изм** — на v0.6 падает (или проверяет старое поведение), проходит после доработки пилота;
  - **П** — новая функция пилота.
- **Данные** — ссылка на набор из раздела 2 или описание прямо в кейсе.
- **Ожидаемый результат** — проверяемое утверждение. Тест считается пройденным, только если выполнены все пункты.

### 1.3 Правила
1. Любое изменение ядра (модель, план, генератор, миграции) не выпускается без прохождения всех тестов **А** (ТЗ НФТ-6, НФТ-9).
2. Каждый исправленный дефект получает регрессионный тест (раздел 5), который падал до исправления.
3. Новое требование в ТЗ добавляется вместе с тест-кейсом в этот документ.
4. Тесты генератора используют фиксированные seed — результат должен воспроизводиться.
5. Если требование изменилось, тест со статусом **есть** переводится в **изм** явно, а не удаляется молча.

### 1.4 Размещение в репозитории
```
tests/
  fixtures/         наборы данных раздела 2 (JSON) + staff_report.xls
  unit/             тесты типа А, по файлу на раздел ФТ (classes.test.ts, curriculum.test.ts…)
  e2e/              тесты типа E
  manual/           чек-листы типа Р (этот документ — источник)
```
До выделения ядра (ТЗ P-T3) тесты типа А запускаются способом из `tests/README.md`: код страницы в Node на заглушке DOM.

## 5. Регрессия

### 5.1 Сквозной сценарий «Обычная школа» (E, каждый выпуск)
1. D-EMPTY. Бот: критериальная; по 2 класса в параллелях 5–7, по 1 в остальных; 1–4 — 5 дней, 5–11 — 6 дней; смена 1; уроков 5/6; импорт D-STAFF; план — да; «Позже».
2. Шаг «Учителя»: назначить предметы 5 учителям.
3. Шаг «Кабинеты»: «Спортзал» (тип «спортзал»); у Физкультуры — тип «спортзал».
4. «Учебный план» 5-A: назначить учителей; «Английский язык» — «Разделить на 2 группы», назначить второго учителя.
5. Сгенерировать.
6. Заблокировать 2 ячейки, перегенерировать.
7. Скачать Excel и копию JSON.
**Ожидаемо:** выполнены инварианты T-8-01…T-8-09; английский 5-A — обе группы в одних и тех же ячейках; Физкультура только в «Спортзале»; заблокированные ячейки на месте; Excel открывается; копия восстанавливается (T-10-05).

### 5.2 Сквозной сценарий «Сложная школа» (А, каждый коммит)
D-MIXED + 5-дневный класс + ДО + дробные часы + урок без учителя + учитель в двух сменах и ДО.
**Ожидаемо:** T-2-17, T-2-19, T-8-01…T-8-12 проходят одновременно.
